# UX-G 복구·검토 문맥 유지 구현 및 검증 보고서

> 완료일: 2026-07-19
> 범위: post-I7 UX-G, fixture-only Frontend usability hardening
> 다음 단계: UX-H Human baseline과 측정 계약 — 시작하지 않음

## 1. 목적

UX-F는 responsive, accessibility와 frozen task의 agent-substitute Gate를 통과했지만 실제
browser 연결 실패에서 Workspace가 raw `Failed to fetch`를 표시했고, 선택한 과거 Step과
모바일 선택지가 component local state에 머물렀다. UX-G는 새 기능이나 company connector를
추가하지 않고 다음 사용성 부채를 닫는다.

- 실패 원인, 판단 영향과 복구 행동을 사용자가 이해할 수 있어야 한다.
- reload와 browser Back/Forward가 검토 문맥을 잃지 않아야 한다.
- deep link가 내부 option ID를 노출하지 않아야 한다.
- canonical primary action을 바꾸지 않으면서 설명용 문구를 한국어 우선으로 표시해야 한다.
- pointer, keyboard와 touch interaction 상태가 일관되어야 한다.

## 2. 구현 내용

### 2.1 안전한 API 오류 경계

`frontend/src/api/client.ts`의 GET/POST transport를 공통 `fetchApi` 경계로 통과시켰다.
browser fetch가 throw하면 원문을 버리고 다음 safe error만 전달한다.

```text
code: CONNECTION_FAILED
message: 의사결정 트윈 서비스에 연결할 수 없습니다.
```

Workspace는 error 객체의 원문을 직접 render하지 않는다. 404, 잘못된 historical Step,
connection failure와 일반 service failure를 분리해 다음 복구 행동을 제공한다.

|상태|사용자 영향|복구 행동|
|---|---|---|
|연결 실패|새 검토 정보를 표시하지 않음|연결 확인 후 다시 시도|
|404|요청한 검토가 없음|결정 목록으로 돌아가기|
|유효하지 않은 과거 Step|해당 시점 재구성 불가|현재 시점 보기|
|기타 service failure|불완전한 정보 비노출|잠시 후 다시 시도|

### 2.2 URL-backed 검토 문맥

Workspace가 다음 query parameter를 source of truth로 사용한다.

```text
?at_step=9&option=2
```

- `at_step`: 사용자에게 보이는 관찰 Step
- `option`: 모바일 비교 카드의 1-based 순번

`option_id`는 URL에 넣지 않는다. 사용자가 선택지를 바꾸거나 현재 Step으로 돌아오면 query를
추가·삭제하고 React UI는 URL에서 직접 상태를 파생한다. 별도 localStorage, global store 또는
동기화 effect를 추가하지 않았다.

검증한 동작은 다음과 같다.

- 과거 Step과 두 번째 선택지를 함께 deep link로 열기
- reload 후 같은 historical boundary와 비교 카드 복원
- Back으로 현재 Step + 두 번째 선택지 복원
- 다시 Back으로 기본 선택지 복원
- 존재하지 않는 Step에서 query를 지우고 현재 시점으로 복구

### 2.3 한국어 우선 supporting copy

Backend enum과 canonical `Simulation Step` action은 변경하지 않았다. presentation 전용 문구만
다음처럼 정리했다.

|이전|UX-G|
|---|---|
|Synthetic fixture|합성 데이터|
|Development Twin|개발 진행 트윈|
|Decision Posture|판단 조건|
|Role별 원문|역할별 원문|
|Guardrail 없음|보호 기준 없음|
|Blocker 변경|대기 원인 변경|
|Milestone|기준점|
|Rollback|되돌리기(Rollback)|
|Commitment Window|선택 가능 기한(Commitment Window)|

실제 팀명, ISP/RTL/BW와 canonical primary action은 번역하지 않는다.

### 2.4 interaction feedback

- primary/secondary button hover, active와 disabled 상태
- link와 disclosure summary hover
- touch tap highlight
- error recovery action group의 responsive wrapping
- 기존 focus-visible, 44px target과 reduced-motion 유지

`transition: all`, 새 animation dependency 또는 JavaScript layout measurement는 추가하지 않았다.

## 3. 테스트 보강

Frontend unit test는 9개에서 12개로 늘었다.

- raw network error 비노출과 한국어 recovery
- historical Step + 모바일 선택지 deep link 복원
- 잘못된 Step에서 현재 시점 복구
- 선택지와 Step 변경 시 query 갱신

Playwright E2E는 7개에서 8개로 늘었다.

- URL query 동시 보존
- reload 복원
- Back/Forward history 복원
- opaque option ID 비노출

기존 complete Replay, 390/640/768/desktop reflow, axe, keyboard, partial Role recovery와 aggregate
conflict test도 그대로 통과했다.

## 5. 변경하지 않은 경계

- Backend domain, projection과 OpenAPI contract
- database schema와 migration
- hidden Outcome/Evaluation boundary
- B2 Role topology와 provider 설정
- simulated Chair의 비권한 경계
- Jira/Confluence, authentication, company data와 write-back
- human reviewer response와 telemetry schema

## 6. 판정과 다음 단계

UX-G 완료 조건을 충족했다. 다만 이 결과는 fixture UI의 복구성과 검토 문맥 유지에 대한
공학적 검증이다. 실제 reviewer comprehension, task time, advice quality 또는 business value를
증명하지 않는다.

다음 UX-H는 다음 입력을 먼저 고정한다.

1. 동일 observable data를 사용한 공정한 baseline fixture pack
2. task 시작·종료, 정답, wrong action, detail open과 복구 event 계약
3. 제작자와 분리된 proxy/domain reviewer
4. 결과 확인 전 고정한 목표와 제외 기준

UX-H 결과 전에는 Inbox/Workspace를 다시 크게 재설계하거나 C0 connector를 시작하지 않는다.
