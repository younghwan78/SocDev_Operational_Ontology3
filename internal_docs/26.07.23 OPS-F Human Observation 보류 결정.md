# OPS-F Human Observation 보류 결정

> 결정일: 2026-07-23
> 결정자: repository owner
> 상태: **DEFERRED — baseline 0/5, product 0/5 유지**
> 후속 상태: **UX-I engineering-proxy 완료; 다음 단계 UX-J**

## 1. 결정

현재 사외·개인 작업 환경에서는 서로 다른 독립 human participant를 condition별 5명씩 확보할 수
없다. 따라서 OPS-F human observation을 현 단계에서 수행하지 않고 사내 또는 독립 참가자를 확보할
수 있는 시점까지 보류한다.

이 결정은 OPS-F를 통과시킨 것이 아니다. 다음 상태를 그대로 유지한다.

- `human_gate_status=not_ready`
- `directional_target_status=not_evaluable`
- `interpretation=no_business_claim`
- baseline 독립 완료 0/5
- product 독립 완료 0/5

Codex, Role Agent 또는 builder가 만든 결과를 human session으로 기록하지 않는다.

## 2. 허용되는 UX-I 범위

UX-I는 측정 기반 개선 대신 `engineering-proxy`로만 진행한다. 다음 근거만 사용할 수 있다.

- OPS-F의 frozen 11-task rubric
- synthetic Project fixture의 실제 API/UI 경로
- accessibility tree와 responsive browser inspection
- unit/E2E, no-future-leakage와 recovery regression
- user가 직접 제시한 한국어 가독성, 전체 상황 우선, raw ID/구현 용어 최소화 요구

허용되는 변경:

- 사용자에게 노출된 구현 용어와 불필요한 raw ID를 사람이 읽는 제목으로 교체
- Portfolio → Situation → Risk → Decision 정보 우선순위와 progressive disclosure 개선
- 중복 정보 축소
- 접근성, 반응형, 오류·부분·과거 시점 복구 개선
- consumer-shaped projection에 필요한 표시용 field 추가

허용하지 않는 주장:

- 사람의 task 시간이 개선됐다
- 오분류율이나 이해도가 개선됐다
- 최종 human UX를 통과했다
- 의사결정 속도, 조언 품질 또는 business value가 개선됐다

## 3. 후속 Gate

UX-I engineering-proxy 완료 조건:

1. 변경할 UX 문제와 expected behavior를 먼저 기록한다.
2. frozen task의 답변 가능성과 epistemic/historical 경계가 회귀하지 않는다.
3. 390px/desktop, keyboard, Axe, overflow와 full E2E가 통과한다.
4. 변경 결과를 Local engineering evidence로만 보고한다.

UX-J와 UX-K도 local engineering Gate로 진행할 수 있다. 다만 UX-K 결과는
`Local fixture UX Release 1`이며 human usability 또는 business value release가 아니다.

OPS-F human observation은 다음 중 하나가 가능해질 때 다시 연다.

- 사외에서 독립 participant를 확보
- 사내 C0/C1에서 실제 사용자와 승인된 study를 실행

재개할 때는 기존 OPS-F release/rubric을 그대로 사용하거나, 변경된 제품을 대상으로 새 release와
protocol revision을 결과 확인 전에 다시 동결한다. 제품 표현만 바뀌고 task, source selector,
target과 rubric 의미가 그대로인 경우에는 protocol을 재사용하되 새 product release hash를 동결한다.
