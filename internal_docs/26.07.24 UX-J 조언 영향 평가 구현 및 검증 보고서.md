## 1. 구현 결과

UX-J는 기존 Demo workflow를 바꾸지 않고 Decision Workspace에 URL 기반
`interaction=evaluation` 모드를 추가했다. 이 모드에서는 다음 순서를 강제한다.

```text
개발 상태·Risk·선택지 검토
  → 조언 전 builder 판단 불변 기록
  → 기존 가상 역할 검토와 simulated decision 생성
  → 명시적 조언 공개 시점 기록
  → accept / modify / reject 사후 판단 불변 기록
```

가상 역할의 의견, simulated decision, Action Plan은 공개 전 접근 가능한 UI에 렌더링하지 않는다.
공개 후에도 builder response가 simulated decision이나 실행 계획을 덮어쓰지 않는다.

## 2. UX 경계

### Demo mode

- 기존 `가상 역할 검토 → 가상 최종 판단 → Simulation Step → 평가` 흐름을 유지한다.
- UX-J response가 없어도 동작한다.
- 기존 fixture 기반 시연과 회귀 테스트에 영향을 주지 않는다.

### 조언 영향 평가 mode

- URL에 `interaction=evaluation`을 보존해 새로고침과 deep link가 동일 mode를 복원한다.
- 조언 전에 선택지, 감수할 Risk, safeguard, 판단 이유를 모두 기록한다.
- 사전 판단을 기록하기 전에는 가상 역할 검토를 시작할 수 없다.
- simulated decision이 준비되어도 `조언 공개 시점 기록` 전에는 조언·실행 내용을 보여주지 않는다.
- 공개 후 `수용`, `수정`, `거부`와 최종 선택·Risk·safeguard·이유를 기록한다.
- `수정`과 `거부`는 조언과 다른 이유를 필수로 요구한다.
- 모든 기록 화면에 local builder engineering proxy이며 사람 평가·승인·사내 기록이 아니라는
  경계를 표시한다.

반응형 form은 `fieldset/legend`, label, name, visible focus, radio semantics, inline alert를
사용한다. 390px에서 가로 overflow 없이 전체 sequence가 동작한다.

## 3. Backend와 저장 계약

ADR-0011과 canonical API contract에 다음 resource를 고정했다.

```text
GET  /api/v1/decision-cases/{case_id}/evaluation-response
POST /api/v1/decision-cases/{case_id}/evaluation-response/initial
POST /api/v1/decision-cases/{case_id}/evaluation-response/advice-reveal
POST /api/v1/decision-cases/{case_id}/evaluation-response/final
```

계약 version:

- `decision-evaluation-response.v1`
- `decision-initial-response-command.v1`
- `decision-advice-reveal-command.v1`
- `decision-final-response-command.v1`

서버 고정 분류:

```text
participant_kind = builder
interpretation   = engineering_proxy_only
```

클라이언트는 actor, participant 권한 또는 advice payload를 제출하지 않는다. Backend가 local actor,
case의 허용 선택지, aggregate version과 최신 persisted simulated decision을 확인한다.

각 단계는 `Idempotency-Key`와 `If-Match`를 사용한다. 동일 key·동일 payload 재시도는 같은 결과를
반환하고, 다른 payload 재사용·단계 역행·두 번째 기록·허용되지 않은 option은 거부한다. `accept`는
조언이 선택지를 지정한 경우 같은 option을 유지해야 한다.

Migration `0021_decision_responses`는
`observable.decision_evaluation_responses`에 `(case_id, actor_id)`당 한 row를 저장한다.
DecisionCase aggregate, simulated decision, Action Plan, Outcome, Evaluation과 Project truth는 변경하지
않는다.
