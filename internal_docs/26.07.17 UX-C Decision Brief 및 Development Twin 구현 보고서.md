# UX-C Decision Brief 및 Development Twin 구현 보고서

> 상태: 구현·검증 완료
> 기준일: 2026-07-17
> 범위: post-I7 UX redesign의 UX-C
> 다음 단계: UX-D 선택지·이견·불확실성 — 시작하지 않음

## 1. 결론

UX-C는 UX-A의 `decision-workspace.v2` 계약을 실제 Backend projection과 사용자 상세 화면에
연결했다. 사용자는 한 화면에서 결정 질문과 기한, 선택 Step의 개발 상태, 변화 원인,
commitment window, 선택지별 예상 변화와 아직 관측되지 않은 결과를 구분할 수 있다.

```text
Stored observable case + validated UX model content
  → selected Step boundary
  → Decision Brief
  → reconstructed track/work/evidence/action state
  → event-based causal chain and blocker propagation
  → model-only commitment and expected transition
  → observed transition remains separate and empty until proven
  → React Decision Workspace
```

## 2. Backend projection

### 2.1 현재와 과거의 공통 read model

`build_workspace_projection_v2`는 현재 Step 또는 `at_step`에서 다음을 조립한다.

- Context header, deadline과 persisted case phase
- phase별 state summary와 primary action
- selected-Step WorkItem, blocker, owner와 next milestone
- 당시 사용 가능·미공개 evidence와 active action
- 관측 event와 dependency 기반 causal chain
- evidence/reversibility/detectability/recoverability/downside/blast-radius/urgency posture
- 실제 case alternative와 explicit expected/observed boundary

현재 phase는 persisted `DecisionCaseStatus`로 결정한다. `CONTEXT_BUILDING`,
`DECISION_REQUIRED`, `ACTIONING`, `VERIFIED`, `CLOSED` 대표 상태가 서로 다른 brief/action을
생성하는 test를 고정했다.

### 2.2 Fail-closed historical boundary

과거 Step에서는 다음을 반환하지 않는다.

- 현재 `case_status`
- 현재 `workspace_phase`
- primary/allowed command action
- 선택 Step 이후 관측된 causal event
- 해당 시점에 검증되지 않은 expected transition model

CASE-VR-001의 earliest Step은 검증된 content에 따라 9다. 그 이전 또는 현재보다 미래 Step은
`DEVELOPMENT_STEP_OUT_OF_RANGE`으로 거부한다. 별도 content가 없는 case는 첫 관측 event
Step, event도 없으면 현재 Step만 허용한다.

### 2.3 Fixture content의 제한된 역할

정적 fixture 전체를 API 응답으로 사용하지 않는다. case ID, fixture version과 option ID가
일치할 때만 commitment window와 expected model content를 가져온다. Step, deadline, track,
evidence와 causal event는 항상 live stored case에서 계산한다.

호환되는 model content가 없으면 각 option을 누락하지 않고 다음처럼 반환한다.

```text
예상 state change: 없음
model basis: 없음
unknown impact: 선택한 Step에서 검증된 상태 전이 모델이 없습니다.
```

## 3. Frontend UX

### 3.1 Decision Brief와 Context Bar

- 결정 목록으로 돌아가기
- 가상 판단, 현재/과거 Step, freshness, workflow phase
- 결정 질문을 H1으로 표시
- 현재 상태 또는 phase recommendation
- 기한과 한 개의 primary action
- `왜 지금`과 blocker downstream impact

모바일에서는 `질문 → 현재 상태 → primary action → 왜 지금` 순서로 표시해 390×844 첫
화면에 primary action이 온전히 보이도록 했다.

### 3.2 Development Twin

- 검증된 범위의 Step selector
- track별 핵심 WorkItem, 담당, blocker와 다음 milestone
- 관측/근거 기반 추론을 구분한 causal chain
- commitment 종료 Step, 닫히는 이유, option loss와 switching cost
- 선택지별 `예상` transition과 별도의 `관측` transition card
- raw event 전체는 접힌 `개발 진행 전체 보기` detail

### 3.3 Decision Posture

근거의 충분성만으로 판단 가능성을 표현하지 않는다. 가역성, 관측 가능성, 복구 가능성,
실패 영향, 영향 범위와 긴급도를 함께 표시하고 설명 문장으로 근거 수·가역 선택지·막힌
track·deadline을 제공한다.

## 6. 남은 경계와 위험

- persisted case status는 phase-adaptive brief를 만들지만 latest case-scoped durable run은 아직
  합성하지 않는다. 따라서 실행 직후 local mutation 진행은 아래 Agent section에 표시되고
  새 Workspace phase에는 반영되지 않는다.
- 결정 이후 observed transition은 decision ID와 development event의 durable 연결이 없어
  `available=false`다. 예상과 실제 비교는 UX-E에서 이 연결을 먼저 구현해야 한다.
- UX model content는 CASE-VR-001만 풍부하다. 다른 case는 개발 상태는 표시하지만
  commitment/expected transition을 unknown으로 보존한다.
- UX-D의 desktop 선택지 비교, Role agreement/dissent, fact/inference/assumption/unknown과
  Role 원문 detail은 시작하지 않았다.
