## 1. 구현 목적과 결론

ENT-A~E는 connector가 만족해야 할 데이터·품질·보안·운영 계약을 검증했지만, 사내 반입 시
무엇이 이미 검증됐고 무엇을 사내에서 새로 확인해야 하는지 구분하는 실행 단위가 없었다.
ENT-F는 이 공백을 문서만으로 메우지 않고 versioned Pydantic contract, YAML template,
SHA-256 manifest와 CLI validator로 고정했다.

핵심 판정은 다음과 같다.

- 사외에서 검증한 코드와 사내에서만 확인 가능한 값이 명시적으로 분리된다.
- 실제 source field/status, network, identity/access, ACL, retention, owner는 추측하지 않고
  `INTERNAL_REQUIRED / UNCONFIRMED_INTERNAL / null`로 남는다.
- pilot은 한 Project, read-only, no write-back, no canonical import로 고정된다.
- `VALIDATE → DRY_RUN → REVIEW → IMPORT → RECONCILE` 순서를 바꿀 수 없다.
- 앞의 세 단계만 로컬 command가 있고 Import/Reconcile에는 의도적으로 command가 없다.
- package는 `READY_FOR_INTERNAL_DISCOVERY`이지 live readiness가 아니다.

## 3. Handoff package 구성

Package root는 `fixtures/enterprise/handoff/`이다.

|파일|내용|현재 값의 성격|
|---|---|---|
|`work-tracker-mapping-template.v1.yaml`|Project, WorkItem, Issue, Event field/status 대상|canonical target만 고정, source 값은 내부 필요|
|`knowledge-base-mapping-template.v1.yaml`|Evidence와 claim/risk/assumption text 대상|canonical target만 고정, source 값은 내부 필요|
|`environment-worksheet.v1.yaml`|runtime/access/governance 11개 항목|모두 null·사내 미확인|
|`pilot-runbook.v1.yaml`|scope, rollback, 5단계, pass/stop, 6개 metric|live 미승인, 결과 미평가|
|`handoff-package.v1.yaml`|위 네 child artifact hash와 checklist|반입 전 무결성 기준|

상위 `fixtures/enterprise/manifest.yaml`도 handoff 다섯 파일을 hash-pinning한다. 따라서 child
artifact와 package manifest가 모두 기존 enterprise fixture 무결성 경계에 포함된다.

## 4. Mapping template

Work-tracker template은 다음 candidate kind를 모두 포함한다.

- `PROJECT`: `project_id`, `title_ko`, lifecycle canonical status
- `WORK_ITEM`: `work_item_id`, `title`, `owner`, canonical work status
- `ISSUE`: `issue_id`, `title`, canonical issue status
- `EVENT`: `event_id`, `summary`, canonical event type

Knowledge-base template은 `EVIDENCE`와 claim/risk/assumption text target을 포함한다. 실제
source system, mapping version, field, status는 모두 `INTERNAL_REQUIRED`다. 특정 제품명,
회사 field ID, URL, label 또는 export 예시는 넣지 않았다.

## 5. Environment worksheet

필수 topic은 다음 11개다.

1. deployment/version
2. network/proxy/certificate
3. identity/access method
4. secret-manager reference
5. ACL/classification
6. retention/deletion
7. rate limit
8. data owner
9. security owner
10. human decision authority
11. model provider policy

모든 사내 항목은 값과 evidence가 null이고 `UNCONFIRMED_INTERNAL`이어야 한다. Identity/access와
secret-manager 항목은 `must_not_commit_value=true`다. 이 파일은 credential을 담는 양식이
아니라, 사내 승인된 secret mechanism의 존재를 별도로 확인하기 위한 template이다.

## 6. Pilot, rollback과 예상 output

Pilot 계약:

```text
max_project_count = 1
allowed_project_refs = []
read_only = true
write_back_enabled = false
canonical_import_authorized = false
live_use_authorized = false
```

Allowlist는 사외 package에서 비워 두며 사내 C1 승인 때 하나만 지정한다. ACL exposure, write
attempt, silent drop/duplicate Event, unknown freshness/reconciliation 차이를 rollback trigger로
고정했다. 조치는 pilot 중지, 저장소 밖 source access 철회, metadata-only audit 보존, mapping
또는 discovery 복귀다.

예상 metric은 ACL exposure, credential leak, write attempt, silent drop, duplicate Event,
reconciliation mismatch이며 모두 목표값 0이다. 현재는 실제 사내 관측이 없으므로 전부
`NOT_EVALUATED`다.

## 7. 고정 실행 순서와 authority

|순서|Stage|Authority|Command|
|---:|---|---|---|
|1|VALIDATE|EXTERNAL_EXECUTABLE|handoff/source contract 검증|
|2|DRY_RUN|EXTERNAL_EXECUTABLE|no-write dry-run report|
|3|REVIEW|EXTERNAL_EXECUTABLE|synthetic security/operation review|
|4|IMPORT|COMPANY_APPROVAL_REQUIRED|없음|
|5|RECONCILE|COMPANY_APPROVAL_REQUIRED|없음|

Import/Reconcile에 command를 추가하면 schema validation이 실패한다. 순서를 바꾸거나 Project
allowlist를 둘 이상 지정해도 실패한다. C0/C1 승인 전 실행 경로가 생기지 않도록 계획 문구가
아니라 contract로 막았다.

- 두 source kind와 5개 candidate kind coverage

## 10. 남아 있는 의도적 공백

다음은 누락이 아니라 사내 C0/C1 승인 전 금지 범위다.

- 실제 source 제품/버전/API와 field/status/label
- 회사 Project/Space ID, URL, user/group, ACL과 classification
- network/proxy/certificate, identity/access 구현, credential 또는 secret value
- retention/deletion, data/security owner와 human approval 결과
- live connector, canonical import, durable sync service와 write-back
- 실제 사내 pilot metric 또는 business value 주장

## 11. 다음 단계

사외에서 계획된 ENT-A~F는 완료됐다. 다음은 사내에서만 가능한 C0 discovery다.

1. 승인된 사내 작업 사본에서 worksheet owner/evidence를 확인한다.
2. vendor/environment 실제 값을 이 public/local fixture repository 밖에서 관리한다.
3. sanitized schema-fit으로 stable identity, version, 네 시간, ACL과 mapping을 검증한다.
4. C1 승인 전에는 Import/Reconcile 구현이나 실행을 시작하지 않는다.
5. 승인 후에도 한 Project read-only pilot과 rollback/reconciliation Gate부터 수행한다.

따라서 현재 최종 판정은 **ENT-F PASS / external preparation complete /
`READY_FOR_INTERNAL_DISCOVERY` / live connection NO-GO**다.
