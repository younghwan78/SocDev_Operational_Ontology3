# UX-A Development Twin 계약 및 Content Fixture 구현 보고서

> 상태: 구현·검증 완료
> 기준일: 2026-07-17
> 범위: post-I7 UX redesign의 UX-A
> 다음 단계: UX-B Decision List — 시작하지 않음

## 1. 결론

UX-A의 목적은 Frontend 화면을 먼저 만드는 것이 아니라, 화면이 Development Twin의
시간·인과·불확실성 경계를 임의로 계산하지 못하도록 Backend source contract와 content
fixture를 고정하는 것이다.

다음 계약을 구현했다.

```text
DecisionWorkspaceProjectionV2
  → selected-step observable state
  → causal chain
  → commitment window
  → option별 expected transition
  → decision 이후 observed transition
  → phase별 primary action
  → pre-reveal outcome boundary
```

CASE-VR-001의 UX fixture는 evaluation corpus와 분리했다. 따라서 frozen evaluation case와
manifest hash를 변경하지 않으며, 아직 API가 계산하지 않는 commitment window와 expected
transition을 실제 구현 완료로 오인하지 않는다.

## 2. 구현 범위

### 2.1 Workspace v2 source contract

`backend/src/soc_ot/application/workspace_contracts.py`에 Pydantic source contract를 추가했다.

- `WorkspaceTimeContext`
  - current/historical mode
  - selected step 범위
  - historical command 금지
  - 다음 evidence step의 시간 경계
- `WorkspaceDevelopmentTwin`
  - 선택 Step 상태
  - observed/inferred causal chain
  - commitment window와 switching cost
- `WorkspaceExpectedOptionTransition`
  - `expected_model` provenance만 허용
  - transition이 있으면 model basis 필수
  - 모델이 모르는 영향은 unknown으로 보존
- `WorkspaceObservedDecisionTransitions`
  - decision과 observed event가 있을 때만 공개
  - expected provenance와 혼용 금지
- `WorkspaceOutcomeAndEvaluation`
  - simulation advance 전 결과·평가·lesson 공개 금지
- `WorkspaceWorkflow`
  - phase별 primary action 하나
  - primary action은 allowed action에 포함
  - stale이면 `REFRESH_STALE`만 primary

Workspace 내부 alternative와 expected transition의 option ID가 정확히 일치해야 하며,
causal event는 selected step 이후 값을 포함할 수 없다.

### 2.2 공통 hidden boundary

Packet 내부에 있던 denylist 재귀 검사를
`backend/src/soc_ot/application/hidden_boundary.py`로 분리했다.

```text
ObservableCasePacket
DecisionWorkspaceProjectionV2
WorkspaceUxFixture
  → 동일 hidden denylist 사용
```

기존 Packet의 error contract는 `_assert_hidden_free` wrapper로 유지했다. 따라서 기존 호출과
test 의미를 바꾸지 않으면서 Workspace fixture에도 같은 경계를 적용한다.

### 2.3 CASE-VR-001 UX content fixture

`fixtures/ux/CASE-VR-001.workspace.v1.yaml`을 추가했다.

- 8개 WorkspacePhase별 상태 설명
- canonical primary action ID와 한국어 label
- READY_FOR_REVIEW의 Workspace v2 예시
- Step 12 개발 상태
- observed/inferred causal chain
- Architecture commitment window
- 두 alternative의 expected transition과 unknown impact
- pre-decision observed transition empty state
- pre-reveal outcome 차단 상태

이 fixture는 UI content와 contract test를 위한 fixture다. evaluation manifest에 포함되지 않고
실제 API projection을 대신하지 않는다.

### 2.4 생성 계약과 한국어 용어

다음 JSON Schema를 Pydantic source에서 생성했다.

- `contracts/generated/decision-workspace.v2.schema.json`
- `contracts/generated/workspace-ux-fixture.v1.schema.json`

`fixtures/dictionaries/labels.ko.yaml`에는 WorkspacePhase, WorkspaceAction과 Development Twin
지식 상태 label을 추가했다. 상세 표현 원칙은
`docs/ui/KOREAN_UI_GLOSSARY.md`에 기록했다.

## 3. 실패 차단 규칙

UX-A test는 다음 오류를 fail-closed로 거부한다.

|오류|거부 code|
|---|---|
|selected step 범위 또는 mode 불일치|`WORKSPACE_STEP_BOUNDARY_INVALID`, `WORKSPACE_TIME_MODE_MISMATCH`|
|과거 Step에서 command 허용|`HISTORICAL_WORKSPACE_COMMAND_FORBIDDEN`|
|selected step 이후 causal event 노출|`FUTURE_CAUSAL_CHAIN_FORBIDDEN`|
|추론 causal link에 inference basis 없음|`INFERRED_CAUSAL_LINK_REQUIRES_BASIS`|
|commitment window 경계 없음|`COMMITMENT_WINDOW_REQUIRES_BOUNDARY`|
|expected/observed provenance 혼용|`EXPECTED_TRANSITION_PROVENANCE_MISMATCH` 등|
|alternative와 expected transition 누락·중복|`EXPECTED_OPTION_TRANSITION_INCOMPLETE` 등|
|simulation advance 전 outcome 공개|`PRE_REVEAL_OUTCOME_MUST_REMAIN_HIDDEN`|
|phase와 primary action 불일치|`WORKSPACE_PHASE_PRIMARY_ACTION_MISMATCH`|
|hidden fixture key 노출|`HIDDEN_FIELD_IN_WORKSPACE_FIXTURE`|

UX-A focused test는 다음을 확인한다.

1. 모든 WorkspacePhase가 정확히 한 번 존재한다.
2. phase, action ID와 한국어 label이 일치한다.
3. historical workspace가 command를 차단한다.
4. 미래 causal event가 과거 화면에 들어오지 않는다.
5. expected, observed와 pre-reveal outcome 경계가 분리된다.
6. hidden field가 fixture에 들어오면 거부한다.
7. 두 source contract가 generated-contract registry에 등록된다.

## 5. 아직 구현하지 않은 것

- Workspace v2 API endpoint 또는 기존 workspace endpoint 교체
- Domain에서 commitment window를 계산하는 service
- Observable rule에서 option별 expected transition을 계산하는 service
- Decision/Action event에서 observed transition을 조립하는 projection
- OpenAPI와 Frontend TypeScript client의 Workspace v2 연결
- Decision List와 Decision Workspace React UI
- 모바일·접근성·E2E 사용성 검증

따라서 현재 사용자가 보는 화면은 바뀌지 않았다. 다음 UX-B도 먼저 기존 v1 API에 임시
업무 규칙을 넣는 방식으로 진행하지 않는다. UX-B에 필요한 list projection 경계를 확인한
뒤 Backend projection과 Frontend 소비 순서를 함께 구현한다.
