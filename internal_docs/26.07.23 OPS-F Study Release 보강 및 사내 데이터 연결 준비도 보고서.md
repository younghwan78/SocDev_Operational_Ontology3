# OPS-F Study Release 보강 및 사내 데이터 연결 준비도 보고서

> 작성일: 2026-07-23
> 범위: synthetic fixture 기반 OPS-F 실행 무결성 보강과 C0 사전 준비도 점검
> OPS-F 소프트웨어 판정: **PASS — 측정 대상 release, reviewer rubric, 제외 관측 집계, Project E2E 고정**
> Human Gate: **NOT READY — baseline 0/5, product 0/5**
> 사내 데이터 직접 연결 판정: **NO-GO — adapter, 시간·ID·ACL·동기화 계약 미구현**
> 허용되는 다음 단계: **C0에서 승인된 sanitized export로 schema-fit 검증**

## 1. 결론

OPS-F protocol v2는 이전 구현만으로도 같은 11개 질문을 baseline과 product에서 수행할 수 있었지만,
어떤 제품 build와 판정표를 사용했는지가 한 artifact로 고정되지 않았고 draft·제외 관측이 결과에서
충분히 드러나지 않았다. 이번 보강으로 다음 경계를 코드와 계약으로 고정했다.

1. 측정 대상 제품의 revision, 진입 경로, UI/API 파일 hash와 실행 환경을 study release로 고정한다.
2. 참가자에게 보이지 않는 reviewer 전용 rubric을 protocol task 순서와 함께 검증한다.
3. draft와 excluded session을 completed 표본에서 분리하고, 고정된 제외 사유별 수를 보고한다.
4. 실제 Project 사용자 경로와 역사 시점 경계를 Playwright로 회귀 검증한다.

다만 이 완료는 **연구 실행 도구가 준비됐다는 뜻**이다. 독립 참가자 관측은 여전히 0건이므로
OPS-F human Gate, UX-I, 의사결정 속도 개선 또는 business value 주장은 열리지 않는다.

현재 Backend는 canonical `DevelopmentProject`를 저장하고 Project 화면에 투영하는 내부 경계는
잘 분리돼 있다. 그러나 Jira/Confluence의 실제 객체를 안전하게 이 계약으로 바꾸는 ingestion 계층은
없다. 따라서 “사내 데이터를 지금 연결해도 문제가 없다”는 판정은 할 수 없다. 현재 상태는
**sanitized export를 이용한 C0 schema-fit 실험을 시작할 기반은 있으나 live read-only connector는
아직 NO-GO**다.

## 2. OPS-F에서 보강한 항목

### 2.1 Study release

`fixtures/usability/OPS-F-20260722.release.v1.yaml`은 다음을 한 묶음으로 고정한다.

|구분|고정 내용|
|---|---|
|Study identity|`OPS-F-20260722-PROJECT-OPERATIONS`|
|Release identity|`OPS-F-PRODUCT-EC2DB27`|
|Product revision|OPS-E 제품 revision `ec2db27e663607d19e0a8cd3b26f06a0c54bd537`|
|시작 위치|`/projects`|
|환경|Chromium, `ko-KR`, 1440×1000, local network|
|UI pin|App, Portfolio, Situation, Risk Detail, Decision Workspace, global CSS|
|API pin|FastAPI route, Project projection policy, generated OpenAPI|
|Study pin|protocol v2, baseline pack v2, reviewer rubric v1|

validator는 모든 경로가 repository 내부의 안전한 상대 경로인지, 파일이 존재하는지, SHA-256이
일치하는지 검사한다. UI/API/study material 세 purpose가 모두 없으면 release 자체를 거부한다.
제품 파일이나 protocol/rubric이 바뀌면 기존 release로 새 session을 준비할 수 없다.

`product_revision`은 사람이 제품 기준 commit을 추적하기 위한 identity이고, 실행 무결성의 직접
검사는 개별 artifact hash가 담당한다. OPS-F 보강 코드와 E2E는 제품 측정 대상에 포함하지 않아
OPS-E UI release를 바꾸지 않는다.

### 2.2 Reviewer-only rubric

`fixtures/usability/OPS-F-20260722.reviewer-rubric.v1.yaml`은 11개 task 각각에 대해 다음을 고정한다.

- PASS에 반드시 포함해야 하는 observable finding
- Issue/Risk/Evidence, 관측/추론/가정 경계를 틀리는 명시적 FAIL 조건
- source 없는 확정, 미래 정보 사용, 다른 Project lesson의 과잉 일반화에 대한 판정 규칙
- Decision/Action/verification/rollback과 Risk 왕복 문맥의 성공 조건

rubric task ID와 순서는 protocol과 정확히 같아야 한다. 참가자 guide에는 rubric을 넣지 않으며,
다음 명령으로 reviewer artifact를 별도로 만든다.

```powershell
uv run soc-ot usability reviewer-guide `
  --output output/usability/OPS-F-20260722/reviewer-guide.md
```

이 구분은 참가자가 정답 문구를 보고 답하는 오염을 막고, reviewer마다 달라지는 사후 채점 기준을
줄인다. 자동 AI 채점이나 사람 승인 대체는 하지 않는다.

### 2.3 Draft와 제외 관측 보존

summary는 condition별로 다음 수를 별도로 계산한다.

- `completed_sessions`: 실제 완료된 session만 포함
- `independent_sessions`: completed 중 protocol이 허용한 proxy/domain 참가자
- `builder_sessions`: completed builder dry-run이며 독립 표본에서 제외
- `draft_sessions`: 시작했지만 완료 판정을 받지 않은 관측
- `excluded_sessions`: protocol의 고정 제외 사유로 제외된 관측
- `exclusion_reasons`: 제외 사유별 count

`EXCLUDED` session의 사유가 frozen protocol 목록에 없으면 validation이 실패한다. 따라서 결과를 본
뒤 편리한 이유를 추가해 표본을 빼는 attrition 왜곡을 줄인다. draft와 excluded는 task accuracy나
elapsed time의 분모에 들어가지 않지만 보고서에서 사라지지 않는다.

### 2.4 실제 Project 경로 E2E

새 E2E는 다음 두 경로를 PostgreSQL-backed API와 실제 browser에서 검증한다.

|경로|검증 내용|
|---|---|
|현재 상태 1440px|Portfolio 우선순위 → PROJECT-V Situation → Risk provenance/impact/treatment → CASE-HO-002 Decision → 원 Risk 복귀|
|역사 상태 390px|PROJECT-V Step 20 → Step 21 emulator conflict/Resource Risk 비노출 → Risk Detail → Decision link가 Project 역사 Step을 Decision timeline으로 오염시키지 않음|

두 경로 모두 page overflow와 Axe 위반을 검사한다. Project fixture reset은 기존 DB의 같은
`fixture_version`/다른 hash가 연구 실행을 오염시키지 않도록 테스트 대상 세 Project만 지운 뒤
canonical import를 다시 수행한다. 이 삭제는 E2E test setup에만 있으며 제품 API에는 노출되지 않는다.

## 3. 사내 데이터 연결 준비도

### 3.1 현재 재사용 가능한 내부 경계

|현재 구현|사내 전환에 주는 가치|판정|
|---|---|---|
|`DevelopmentProject` strict validation|Issue, Risk, Evidence, Event, WorkItem, Milestone, Decision reference와 역사 일관성을 fail-closed 검증|재사용 가능|
|`ProjectRepository` Protocol|application projection이 PostgreSQL 구현 세부와 분리됨|재사용 가능|
|PostgreSQL aggregate + optimistic version|한 Project snapshot의 원자적 교체와 충돌 감지|제한적으로 재사용 가능|
|deterministic Portfolio/Situation/Risk projection|source 종류와 무관하게 canonical payload를 같은 UI로 표시|재사용 가능|
|`effective_at_step`/`observed_at_step` replay|로컬 logical Step에서 no-future-leakage 검증|기업 시간 계약으로 직접 사용 불가|
|source/Evidence/Risk provenance|사내 link를 canonical source reference로 보존할 자리 제공|확장 필요|
|Frontend read path|Backend가 만든 projection만 소비하고 source connector를 직접 알지 않음|재사용 가능|

즉, **canonical model 이후의 저장·projection·UX는 connector 독립적**이다. 문제는 그 앞단인 실제
source 수집, identity/시간 변환, 권한 필터와 변경 동기화가 아직 존재하지 않는다는 점이다.

### 3.2 현재 live 연결을 막는 필수 공백

|공백|현재 상태|연결 시 발생 가능한 문제|최소 C0/C1 조건|
|---|---|---|---|
|Jira/Confluence adapter|whole YAML fixture import만 존재|custom field, page 구조, link를 임의 해석|source별 read-only adapter와 mapping test|
|Enterprise identity|local string ID만 존재|site/project/issue/page 간 충돌, rename·move 추적 실패|tenant+object type+external ID+version의 stable key|
|Enterprise time|logical integer Step만 존재|수정 시각을 발생 시각으로 오인, 과거 화면에 미래 내용 노출|valid/effective, observed, source-updated, ingested time 계약|
|ACL·authentication|local actor, endpoint 인증 없음|허용되지 않은 Project/Issue/Confluence 내용 노출|source ACL 상속, user identity, deny-by-default query|
|Incremental sync|cursor/webhook/idempotency 없음|중복 Event, 누락 update, 순서 뒤바뀜|cursor, content hash, retry, tombstone, reconciliation|
|삭제·retention|정책과 source tombstone 없음|삭제된 문서가 projection에 잔존|deletion state, retention, reindex/erase 절차|
|Data classification|분류·redaction field 없음|제한 정보가 model prompt/log/UI로 전파|classification allowlist와 pre-ingestion redaction|
|Unstructured extraction|Confluence parser/review 없음|문장 추출을 FACT로 과신|candidate claim/evidence + human validation|
|Project↔DecisionCase mapping|fixture reference만 수동 작성|잘못된 Risk/Decision 연결|stable external relation mapping과 unmatched queue|
|Portfolio scale|전체 aggregate를 모두 list|Project 수 증가 시 지연·권한 필터 비용 증가|pagination/filter/index와 scoped repository read|
|운영 관측성|connector audit/lag/DLQ 없음|누락·stale data를 사용자가 최신으로 오인|sync audit, freshness SLO, quarantine/DLQ|

가장 중요한 차단점은 ACL과 시간 의미다. 현재 API는 저장된 Project를 인증 없이 모두 읽을 수 있고,
local Step은 Jira/Confluence의 업무 시간을 대표하지 않는다. connector만 추가하면 화면은 보일 수
있지만, 안전하고 역사적으로 정확한 operational twin이 되지는 않는다.

## 4. C0에서 먼저 고정할 enterprise ingestion 계약

실제 회사 source마다 바로 `DevelopmentProject`를 생성하지 말고, source-neutral envelope를 먼저
통과시키는 것이 안전하다. 최소 envelope는 다음 의미를 가져야 한다.

|Field|의미|
|---|---|
|`source_system` / `source_tenant`|Jira/Confluence와 배포 tenant 구분|
|`source_object_type` / `external_id`|Issue, page, comment, attachment, sprint 등 stable identity|
|`external_version` / `content_hash`|동일 version 재처리와 내용 변경 판정|
|`effective_at`|업무상 상태 변화가 효력을 가진 시각|
|`observed_at`|조직이 그 변화를 알 수 있게 된 시각|
|`source_updated_at`|source system이 기록한 수정 시각|
|`ingested_at`|twin이 실제로 수집한 시각|
|`source_acl_ref`|원 source의 접근 범위 참조|
|`classification`|model/UI로 보낼 수 있는지 결정하는 분류|
|`source_url`|사용자가 원문을 검증할 read-only link|
|`deletion_state`|active/deleted/restricted 상태|

mapping 결과는 곧바로 FACT로 승격하기보다 다음 두 층으로 분리해야 한다.

1. **정형 mapping**: Jira status/history, named field와 명시적 link처럼 규칙으로 보존 가능한 값
2. **candidate extraction**: Confluence 본문에서 추출한 claim, risk, assumption 후보

candidate extraction은 source span, extractor version, confidence와 review status를 보존하고 사람
검토 전에는 canonical FACT가 될 수 없다. Role Agent는 이 ingestion 판단을 대신하지 않으며,
검증된 `ObservableCasePacket` 또는 Project projection만 받는 기존 hidden/source 경계를 유지한다.

## 5. 권장 전환 순서

### C0-A. Sanitized export schema-fit

- 회사 승인 후 한 Project의 비식별 Jira JSON/CSV와 Confluence export를 준비한다.
- connector 없이 offline importer에서 envelope로 정규화한다.
- unmapped field, dangling relation, time ambiguity, ACL/classification 누락률을 보고한다.
- canonical `DevelopmentProject` validation을 통과하지 못한 항목은 버리지 않고 quarantine한다.
- 이 단계 산출물과 실제 회사 data는 이 public/local repository에 commit하지 않는다.

### C0-B. Mapping과 보안 계약 동결

- Jira/Confluence version, auth 방식, API rate limit과 custom field 사전을 확정한다.
- source ACL 계승과 deny-by-default query를 설계한다.
- enterprise time, deletion, retention, attachment, redaction 정책을 ADR로 승인한다.
- 한 Project allowlist와 pilot owner/data owner/human decision authority를 지정한다.

### C1-A. One-project read-only adapter

- 별도 private deployment에서 한 Project/Space만 polling으로 읽는다.
- cursor/content hash/idempotency, retry와 reconciliation을 검증한다.
- source freshness와 mapping failure를 사용자에게 표시한다.
- write-back, Jira transition, Confluence 수정과 실제 승인은 넣지 않는다.

### C1-B. Operational pilot

- 최소 historical/prospective case와 독립 reference set을 protocol에 맞춰 수집한다.
- Situation-to-Decision time, Evidence preparation time, critical impact recall과 safeguard completeness를 측정한다.
- small sample은 directional signal로만 보고하고, usability와 data-quality 실패를 분리한다.

### C2. Controlled write-back

C1의 가치·보안 Gate 통과 뒤 별도 승인으로만 시작한다. draft preview, named human approval,
idempotency key, field/action allowlist, audit와 rollback/compensation이 필수다.
