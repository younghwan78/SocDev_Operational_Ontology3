> 작성일: 2026-07-17

> 범위: synthetic fixture, ReplayProvider, normal user UI
> Frozen task evidence: `output/usability/UX-F-20260717-CASE-VR-001/report.md`

## 1. 결론

UX-F의 구현·자동화·대리 evaluator Gate를 통과했다.

- 390px, 768px, desktop과 200% zoom 등가 리플로우에서 page-level 수평 scroll이 없다.
- keyboard 첫 진입에서 본문 건너뛰기가 노출되고 본문으로 focus가 이동한다.
- screen reader 접근성 tree가 main, navigation, region, heading, table, status와 alert를 구분한다.
- partial review는 완료/실패 Role과 재시도 경로를 보여주며 Chair 실행을 차단한다.
- aggregate version conflict는 stale alert와 최신 상태 복구 action을 제공한다.
- CASE-VR-001의 canonical 8개와 Development Twin 5개 질문을 normal UI에서 모두 답했다.
- 질문 1~6 수행 중 Role 원문, raw JSON 또는 ontology graph를 열지 않았다.
- historical Step, expected/observed와 hidden outcome 경계가 유지된다.

이 판정은 집에서 human approver를 대신한 Codex evaluator와 deterministic browser automation의
공학적 Gate다. 실제 사람의 이해도, task time, 의사결정 속도나 조언 품질은 증명하지 않는다.

## 2. 구현한 보완

### 2.1 Keyboard와 focus

- 모든 route에 `본문으로 건너뛰기`를 하나만 제공했다.
- 각 화면의 `main#main-content`는 hash navigation 뒤 programmatic focus를 받는다.
- 상단의 보기 action은 scroll만 하지 않고 대상 section으로 focus도 이동한다.
- `prefers-reduced-motion`에서는 programmatic smooth scroll을 사용하지 않는다.
- link, button, select, summary와 section focus에 동일한 visible focus ring을 적용했다.

### 2.2 Responsive와 zoom

- 전역 `border-box`로 padding과 border가 component 폭을 넘지 않게 했다.
- 한국어 heading과 긴 상태 문장은 줄바꿈 가능하도록 했다.
- 701–800px의 Workspace padding과 Decision Brief column 폭을 별도로 조정했다.
- 700px 이하는 기존 mobile card/one-column 구조를 유지한다.
- select의 foreground/background를 명시해 native control contrast가 theme에 흔들리지 않게 했다.
- 주요 button, back link, select와 disclosure summary의 높이를 44px 이상으로 고정했다.

200% zoom은 1280px reference viewport가 640 CSS px로 reflow된 것과 같은 조건으로 자동화했다.
이는 pinch zoom 확대가 아니라 WCAG reflow 관점의 deterministic 대리 측정이다.

### 2.3 Recovery copy와 정보 경계

partial review에서 provider error code와 runtime Role ID를 일반 사용자에게 그대로 노출하지 않는다.

- runtime Role ID → Architecture, HW/RTL, SW/FW/HAL, Verification/Measurement, Technical PM
- provider failure → 실행 한도 초과, 응답 검증 실패, 재시도 한도 초과, 역할 검토 실패

오류 문장은 실패 사실만 말하지 않고 새로고침, 완료 상태 확인, 재시도처럼 다음 복구 행동을
함께 안내한다. partial 상태에서는 완료 Role과 실패 Role을 분리하고 재시도만 제공하며 가상
최종 판단 action은 표시하지 않는다.

## 5. Partial·stale·conflict E2E

### 5.1 Partial

browser-state E2E에서 Dossier run을 `PARTIALLY_COMPLETED`로 고정했다.

- 완료: Architecture, Verification/Measurement, Technical PM
- 실패: SW/FW/HAL · 응답 검증 실패
- 내부 `PROVIDER_ATTEMPT_FAILED` 문자열: 화면에 없음
- 가상 역할 검토 재시도: 표시
- 가상 최종 판단: 표시하지 않음

Backend의 실제 partial 상태 생성과 Chair 차단은 기존 I5 test가 담당한다. UX-F E2E는 그 상태를
받은 browser의 설명과 복구 action을 검증한다.

### 5.2 Stale/conflict

command의 `CASE_VERSION_CONFLICT`를 409로 재현했다.

- `개발 상태가 변경되었습니다` alert 표시
- 기존 primary action 비활성화
- `최신 상태 불러오기` 실행
- command error reset과 current Workspace 복구

stale는 conflict의 사용자 projection이므로 한 E2E에서 원인과 복구 화면을 연결했다.

## 8. UX-F 이후 남은 경계

UX-F 완료 뒤 로컬 계획에서 남은 구현 미완료가 자동으로 C0를 승인하지는 않는다.

- 실제 Multimedia System/Architecture Reviewer의 comprehension과 task time
- 기존 업무 대비 Situation-to-Decision Time baseline과 개선 폭
- 실제 SoC DevelopmentEvent의 event completeness
- 기업 browser, screen reader와 200% native zoom 반복 검증
- Jira/Confluence read-only connector, ACL, 인증과 company data classification
- human decision authority와 write-back 승인
- 선택 사항인 I7 Responses API gate의 key·가격·비용 승인

따라서 다음 제품 검증은 사내 연동 구현이 아니라 먼저 human baseline protocol과 C0 입력을
확정하는 것이다. 그 전까지 시스템은 fixture-only simulated decision support다.
