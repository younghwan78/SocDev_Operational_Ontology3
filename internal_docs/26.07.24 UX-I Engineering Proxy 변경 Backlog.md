# UX-I Engineering Proxy 변경 Backlog

> 작성일: 2026-07-24
> 범위: synthetic fixture 기반 Local PoC
> 근거 수준: **engineering-proxy — human observation 아님**
> Human Gate: **NOT READY — baseline 0/5, product 0/5 유지**

## 1. 목적

OPS-F human observation을 보류한 상태에서 UX-I를 사람 측정 결과처럼 해석하지 않고 진행한다.
현재 Project 사용자 경로를 실제 브라우저, accessibility tree, API projection과 frozen task로
검토해 사용자가 과제 상황을 읽는 데 방해가 되는 표현 문제만 최소 변경한다.

새 dashboard, 검색, filter, ontology 탐색기, enterprise connector는 추가하지 않는다.
Decision Workspace의 selected/current와 관측·예상·미확인 경계는 현재 회귀 근거가 없으므로
이번 단계에서 구조를 바꾸지 않는다.

## 2. 변경 전 고정 문제

|우선순위|문제|관측 위치|위험|Expected behavior|
|---:|---|---|---|---|
|P1|가장 가까운 기준점과 Track의 다음 기준점이 raw ID로 먼저 보임|Portfolio, Situation 개발 진행|사용자가 ID를 해석해야 과제 진행을 파악할 수 있음|사람이 읽는 기준점 제목을 기본 표시하고 canonical ID는 API 추적용으로 유지|
|P2|전체 상황의 판정 근거가 raw source ID 목록으로 보임|Situation 전체 상황|왜 먼저 봐야 하는지 이해하려면 아래 객체를 다시 찾아야 함|현재 Step에서 보이는 작업·Risk·Issue·Evidence·기준점·Event 제목으로 표시하고 미해결 ref만 ID로 fallback|
|P3|`Backend`, `source reference`, `ordering policy` 같은 구현 용어가 사용자 설명에 노출됨|Portfolio lead, Situation Risk 설명|도메인 의미보다 시스템 구현 방식을 먼저 읽게 됨|막힌 작업·Risk·기준점·현재 Step 근거라는 도메인 언어로 설명|

## 3. 변경하지 않을 항목

- Risk ordering과 Project attention policy
- current/historical `at_step` 경계와 no-future-leakage
- Risk source ID와 canonical ID 자체
- Portfolio → Situation → Risk → Decision 왕복
- simulated Chair와 실제 승인 권한 경계
- 검색, filter, pagination, virtualization

## 4. 검증 계약

1. Backend projection은 Portfolio 기준점의 ID와 제목을 함께 제공한다.
2. Portfolio와 Situation의 기본 읽기 화면에는 알려진 기준점·source의 raw ID 대신 제목이 보인다.
3. 알 수 없는 source ref는 숨기지 않고 canonical ID로 fallback한다.
4. frozen Project task, historical Step, Decision 왕복과 raw-detail 접근이 회귀하지 않는다.
5. desktop·390px에서 overflow가 없고 keyboard, Axe와 full E2E가 통과한다.

이 변경은 사람의 task-time, 이해도, 의사결정 속도, 조언 품질 또는 business value 개선 근거로
사용하지 않는다.
