# ENT-A Source-neutral Ingestion 계약 구현 및 검증 보고서

> 작성일: 2026-07-24  
> 범위: synthetic fixture-only enterprise preparation  
> 판정: **ENT-A PASS, NEXT ENT-B**

## 1. 구현 목적

ENT-A는 실제 Jira/Confluence source를 바로 `DevelopmentProject`로 변환하지 않도록 중간 경계를
만든다. 이 경계는 source의 identity, version, 서로 다른 시간 의미, 접근 정보와 삭제 상태를
보존하지만 canonical Project/Issue/Risk/Evidence/Event 또는 FACT를 생성하지 않는다.

ADR-0012는 다음 순서를 승인한다.

```text
future source adapter
  → enterprise-source-record.v1 validation
  → ENT-B mapping candidate
  → ENT-D review/quarantine
  → approved canonical import
```

ENT-A에는 future source adapter 이후 단계의 구현이 포함되지 않는다.

## 2. 계약

`EnterpriseSourceRecord`는 다음을 필수로 보존한다.

|영역|필드와 규칙|
|---|---|
|Stable identity|`source_system`, `source_tenant`, `source_object_type`, `external_id`|
|Change identity|`external_version`, lowercase SHA-256 `content_hash`|
|Enterprise time|timezone-aware `effective_at`, `observed_at`, `source_updated_at`, `ingested_at`|
|Provenance|credential이 포함되지 않은 read-only `source_url`|
|Access metadata|opaque `source_acl_ref`, `PUBLIC/INTERNAL/CONFIDENTIAL/RESTRICTED`|
|Availability|`ACTIVE/DELETED/RESTRICTED`|
|Content|`ACTIVE`만 JSON object payload 허용|

Title, URL, version, hash와 payload가 바뀌어도 stable identity는 유지된다. `DELETED` 또는
`RESTRICTED` record는 payload를 가질 수 없어 삭제·권한 축소 이후 content가 envelope를 통해
계속 전달되지 않는다.

## 3. 시간 의미

네 시각은 서로 대체하지 않는다.

- `effective_at`: 업무 상태가 효력을 가지는 시각
- `observed_at`: 조직이 상태를 알 수 있게 된 시각
- `source_updated_at`: source system이 주장하는 수정 시각
- `ingested_at`: twin이 envelope를 수집한 시각

모든 값은 timezone을 요구한다. 계획된 상태는 effective 이전에 observed될 수 있고, 늦게 도착한
자료는 effective 이후에 ingested될 수 있으므로 ENT-A는 임의의 대소 관계를 강제하지 않는다.
시간 충돌과 모호성의 accept/quarantine/reject 정책은 ENT-B/ENT-D가 소유한다. Local
`Simulation Step`을 enterprise timestamp로 변환하지 않는다.

## 4. Application port

```text
SourceReader.read(identity) -> EnterpriseSourceRecord | None
IngestionSink.write(record) -> None
```

두 Protocol은 validated envelope만 주고받으며 FastAPI, SQLAlchemy, provider 또는 vendor SDK를
import하지 않는다. `IngestionSink`는 source record staging 경계일 뿐 canonical truth write port가
아니다. Agent와 `ObservableCasePacket`에도 raw enterprise record를 전달하지 않는다.

## 5. 실패 경계

다음 입력은 validation 단계에서 거부한다.

- timezone이 없는 네 종류의 time
- ACL reference 또는 classification 누락
- uppercase/잘못된 SHA-256
- embedded credential이 있는 source URL
- ACTIVE인데 payload가 없는 record
- DELETED/RESTRICTED인데 payload가 남은 record
- 계약에 정의되지 않은 company-specific field

## 7. 범위 밖과 다음 단계

ENT-A에 포함되지 않은 항목:

- Jira/Confluence SDK와 실제 API 호출
- 회사 field ID, tenant, URL, data, principal ACL과 credential
- mapping profile과 unstructured extraction
- cursor, pagination, retry, reconciliation과 tombstone 처리
- dry-run, diff, quarantine와 resolution
- authentication, retention과 write-back

다음 고정 단계 ENT-B는 synthetic dirty export fixture와 mapping registry를 구현한다. 모든 입력을
명시적으로 accept, quarantine 또는 reject하고, source span과 mapping/extractor version이 없는
candidate를 생성하지 않으며, 사람 검토 전 unstructured extraction을 FACT로 승격하지 않아야 한다.
