## 1. 구현 결과

UX-K는 UX-I의 정보 구조와 UX-J의 builder/Agent 분리 흐름을 한 사용자 여정으로 연결해
Local fixture UX Release 1로 동결했다.

```text
Portfolio
  → Project 전체 상황·막힌 WorkItem/Gate
  → top/remaining Risk와 source·inference·영향
  → Decision 선택지·이견·안전 조건
  → 조언 전 builder 판단 불변 기록
  → 가상 역할 검토와 명시적 advice reveal
  → accept / modify / reject 최종 판단
  → Action / Outcome / Process·Outcome Evaluation
  → 원 Project/Risk 문맥 복귀
```

Project V의 `RISK-V-WRONG-COMMIT`과 `CASE-HO-002`를 사용한 브라우저 시나리오가 이 전체
경로를 하나의 테스트에서 수행한다. Agent output은 계속 simulated advice이며 사람 승인이나
canonical truth를 대체하지 않는다.

## 2. UX-K에서 발견하고 닫은 경계

평가가 완료된 fixture에 `lessons_ko`가 비어 있으면 Backend workflow는 `VIEW_LEARNING_SUMMARY`를
주 행동으로 제공하지만, 기존 UI는 학습 section 자체를 렌더링하지 않았다. 따라서 버튼은 보이지만
이동할 도착 지점이 없는 상태였다.

수정 후에는 평가가 완료되면 항상 focus 가능한 `#learning` section을 렌더링한다. 새 학습이 없으면
“이번 fixture 결과에 기록된 추가 학습은 없습니다.”라고 명시한다. 행동 계약과 화면 도착 지점이
일치하고, keyboard 사용자도 같은 위치로 이동한다. `matchMedia`와 `scrollIntoView`가 없는 제한된
환경에서도 focus 동작이 안전하게 유지된다.
