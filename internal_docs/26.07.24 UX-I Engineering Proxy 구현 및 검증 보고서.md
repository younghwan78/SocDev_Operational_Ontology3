## 1. 결론

UX-I는 사람 관찰 없이 이해도나 속도를 추정하지 않았다. 변경 전에 동결한 세 문제만 수정했다.

1. Portfolio와 Track에서 raw milestone ID가 제목보다 먼저 보였다.
2. Situation의 주의 판정 근거가 raw source ID로 보였다.
3. `Backend`, `source reference`, `ordering policy` 같은 구현 용어가 사용자 설명에 노출됐다.

결과적으로 Portfolio → Situation의 첫 읽기 경로는 사람이 읽는 기준점과 source 제목을 기본으로
표시한다. canonical ID, 정책, source identity, 역사 시점과 Decision 왕복은 유지했다.

## 2. Backend 설계

`project-list-item.v1` projection에 `nearest_milestone_title`을 additive field로 추가했다.
Portfolio가 fixture나 ID naming convention을 다시 해석하지 않고 바로 표시할 수 있게 한
consumer-shaped field다.

- `nearest_milestone_id`: canonical 추적·정렬 기준으로 유지
- `nearest_milestone_title`: 기본 사용자 표시
- `nearest_milestone_step`: Step 거리 계산에 유지

Project attention과 Risk ordering policy에는 손대지 않았다. 생성 JSON Schema, OpenAPI와
TypeScript client를 함께 갱신했다.

## 3. Frontend 설계

### 3.1 Portfolio

- “Backend가 계산한 순서”를 막힌 작업, 활성 Risk와 가까운 기준점이라는 도메인 설명으로 교체했다.
- 가장 가까운 기준점은 raw ID 대신 Backend projection의 제목을 표시한다.

### 3.2 Situation

- 현재 Step에서 보이는 Track, WorkItem, Milestone, Issue, Risk, Evidence, Decision과 Event를
  `reference → title` map으로 한 번 구성한다.
- 주의 판정 source ref는 제목으로 표시한다.
- 알 수 없는 ref는 숨기지 않고 원래 ID로 fallback한다.
- Track의 다음 기준점은 Situation milestone 제목으로 표시한다.
- Risk 정렬과 source 설명을 구현 용어 대신 실패 영향·긴급성·비가역성·현재 Step 근거로 표현한다.

별도 library, client state 또는 data fetching을 추가하지 않았다. 두 독립 query는 기존처럼 병렬로
실행되고 title map은 `useMemo`로 projection이 바뀔 때만 재구성된다.

## 4. 보존한 경계

- `project-attention.v1`, `project-risk-order.v1`
- canonical milestone/source ID와 unknown-ref fallback
- current/historical `at_step`와 no-future-leakage
- Portfolio → Situation → Risk → Decision → Risk 왕복
- raw Risk source detail
- simulated Chair의 비권한 경계
- synthetic fixture only, read-only Project API

검색, filter, pagination, virtualization과 enterprise connector는 추가하지 않았다.
Decision Workspace의 selected/current 구조도 이번 근거로 바꾸지 않았다.

## 5. Release 동결

기존 `OPS-F-PRODUCT-EC2DB27`은 당시 제품을 설명하는 역사 artifact로 보존했다. UX-I 제품 변경은
먼저 `87d49d7`로 커밋한 뒤 새 `UX-I-20260724.release.v1.yaml`에서 다음을 고정했다.

- 제품 commit과 `/projects` 진입점
- Project/Decision UI와 CSS
- Project API projection과 OpenAPI
- 변경되지 않은 OPS-F protocol, baseline pack과 reviewer rubric

task, source selector, target과 rubric 의미가 변하지 않았으므로 protocol은 재사용했다. 이후 이 중
하나라도 바뀌면 사람 관찰 전에 새 protocol revision을 별도로 동결해야 한다.
