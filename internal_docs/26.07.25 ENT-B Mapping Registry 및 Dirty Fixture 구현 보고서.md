## 1. 구현 결과

ENT-B는 validated `EnterpriseSourceRecord`를 canonical domain object가 아닌 reviewable candidate로
변환한다. 핵심 순서는 다음과 같다.

```text
enterprise-source-record.v1
  → versioned mapping profile resolution
  → field/status mapping + source span
  → structured/unstructured candidate
  → ACCEPT | QUARANTINE | REJECT
```

`ACCEPT`는 candidate 생성 성공만 의미한다. canonical Project import, 사람 승인, 실제 source 반영
또는 write-back을 의미하지 않는다.

## 2. Mapping registry

`enterprise-mapping-registry.v1`은 exact `(source_system, source_object_type)`별 profile을 고정한다.

|Profile|Source|Candidate|
|---|---|---|
|`synthetic-project.1`|generic work tracker의 project|PROJECT|
|`synthetic-work-item.1`|generic work tracker의 work-item|WORK_ITEM|
|`synthetic-issue.1`|generic work tracker의 issue|ISSUE|
|`synthetic-event.1`|generic work tracker의 event|EVENT|
|`synthetic-knowledge-page.1`|generic knowledge base의 page|EVIDENCE + CLAIM/RISK/ASSUMPTION|

각 profile은 required field, direct field mapping, status mapping, mapping version, extractor version과
late-arrival threshold를 보존한다. 중복 profile ID나 source key, 불완전 status mapping은 validation
단계에서 거부한다.

## 3. Candidate provenance

Structured candidate는 다음 provenance를 필수로 가진다.

- stable source identity와 external version
- mapping profile ID와 mapping version
- mapped field values
- 각 값의 JSON-pointer source span

Unstructured candidate는 extractor version, 정확한 character offset과
`review_status=UNREVIEWED`를 추가로 요구한다. 종류는 CLAIM, RISK, ASSUMPTION으로 제한되며 FACT나
reviewed 상태를 입력할 수 없다. Synthetic extractor는 근거 없는 confidence를 만들지 않고
`extractor_confidence=null`을 기록한다.

## 4. Dirty fixture corpus

`fixtures/enterprise/manifest.yaml`이 registry와 corpus의 SHA-256을 고정한다.

|Pattern|판정|
|---|---|
|NORMAL|ACCEPT / MAPPED|
|MISSING_FIELD|QUARANTINE / REQUIRED_FIELD_MISSING|
|UNKNOWN_STATUS|QUARANTINE / STATUS_UNMAPPED|
|DUPLICATE_UPDATE|첫 record ACCEPT, 반복 record REJECT|
|OUT_OF_ORDER_EVENT|새 상태 ACCEPT, 뒤늦은 과거 update QUARANTINE|
|MOVED_PAGE|ACCEPT / SOURCE_URL_CHANGED|
|DELETED_OBJECT|ACCEPT / metadata-only EVENT|
|RESTRICTED_OBJECT|ACCEPT / metadata-only EVENT|
|CONFLICTING_SOURCE|동일 version의 다른 hash QUARANTINE|
|LATE_EVIDENCE|ACCEPT / LATE_ARRIVAL + unreviewed candidates|

Corpus는 `synthetic-work-tracker`와 `synthetic-knowledge-base`만 사용한다. 실제 Jira/Confluence field,
tenant, URL, principal, credential과 회사 data는 포함하지 않는다.

## 5. 결정 경계

```text
ACCEPT      = candidate 생성 가능, canonical import 권한 아님
QUARANTINE  = source ambiguity/conflict로 후속 resolution 필요
REJECT      = candidate를 생성하지 않음
```

삭제·접근 제한 record는 ENT-A에 의해 payload가 제거되어 있다. ENT-B는 상태 정보만 EVENT
candidate로 만들며 실제 tombstone 또는 ACL 축소를 canonical storage에 적용하지 않는다.
