# Step 4 인접 Topology Ablation 구현 보고서

> 상태: 구현·live ablation 완료, B2 stability 대기
> 기준일: 2026-07-14
> 범위: local fixture-only PoC, I7 후속 구현 Step 4

## 1. 목표

기존 ablation은 B3와 B1을 직접 비교해 독립 Role Agent의 가치와
Challenger·simulated Chair의 가치를 섞었다. Step 4는 같은 frozen v2 case에서
인접 topology의 추가 가치와 품질 후퇴를 각각 계산해 다음 네 결과를 모두 표현한다.

```text
keep_b3 | release_b2 | release_b1 | release_b0
```

Agent prompt, hidden outcome, expected result와 decision policy는 변경하지 않았다.

## 2. 구현 결과

`AblationEvaluation`을 `ablation-evaluation.v2`로 올리고 세 delta를 추가했다.

|Delta|최소 기준|의미|
|---|---:|---|
|B1 over B0|1/4|단일 전문 Agent의 최소 유효성|
|B2 over B1|3/4|독립 Role Agent의 다관점 가치|
|B3 over B2|3/4|Challenger·Chair의 별도 가치|

각 delta는 marginal case ID, quality regression case ID, policy failure case ID를
분리한다. 후보는 모든 fresh case에서 Process gate를 통과하고 baseline의 true 항목을
false로 후퇴시키지 않아야 한다.

추가 가치는 새 Role ID의 unique concern, 새 safeguard metric, 검증된 Challenger
objection, deterministic false-to-true 개선만 인정한다. 표현이 달라졌다는 이유만으로
가치를 세지 않는다.

## 3. 선택과 artifact

선택 우선순위는 B3, B2, B1, B0 순이다. 선택 topology와 stop rule을 별도 필드로
저장하고, 선택 topology가 모든 Process gate를 통과했는지는
`release_gate_passed`로 분리한다. CLI는 이 gate가 false이면 exit code 1을 반환한다.

Ablation `report.md`는 전체 16개 비교 run과 선택 topology의 4개 case 결과를 구분한다.
`policy_violations.json`은 선택 topology에 한해 release gate를 설명하며 B0-B3 전체
Process score는 비교 자료로 계속 보존한다.

## 4. Replay 검증의 해석

Replay 기반 test double에서 세 delta가 모두 4/4로 계산되고 `keep_b3`가 선택되는 것은
구현 회귀가 없다는 뜻이다. 같은 문구나 수치를 실제 Agent topology 채택 근거로
사용하지 않는다. 실제 근거는 frozen `eval-2026-07-14.2`에 대한 Codex CLI 또는
Responses API live 결과여야 한다.

## 5. 실제 Codex CLI ablation 결과

`gpt-5.6-luna`, reasoning `high`, parallelism 2로 frozen v2의 validation 2개와
sealed-unseen 2개를 한 번씩 실행했다. Aggregate 결과만 확인했고 개별 sealed 실패
원인이나 hidden outcome은 열지 않았다.

|항목|결과|
|---|---|
|실행 규모|16 topology runs, 최대 52 semantic calls|
|B2 over B1|4/4|
|B3 over B2|0/4|
|선택|`release_b2`, selected topology `B2`|
|선택 topology gate|4/4 PASS|
|Runtime failure / policy violation|0 / 0|
|사용량|input 515,434 / output 32,198 tokens|
|실행 시간|411.6초|
|Artifact|`output/evaluations/eval-2026-07-14.2/20260714T151056Z-codex-cli-5b1d7bab/`|

결론은 독립 Role Agent B2가 단일 Agent B1보다 4개 case 모두에서 추가 가치를
만들었지만, Challenger·simulated Chair B3는 B2 위에 별도 가치를 추가하지 못했다는
것이다. 따라서 Step 4의 release candidate는 B2다. 이는 집의 synthetic fixture에
대한 결과이며 실제 업무 가치나 사내 일반화를 증명하지 않는다.

## 7. 남은 경계

- Step 4는 topology ablation과 선택 계약만 다룬다.
- B2 validation x5와 sealed-unseen x3 stability는 별도 후속 gate다.
- 현재 stability runner는 B3 전용이므로 B2 evidence로 실행하지 않는다.
- Stability 통과 전에는 durable dossier workflow의 B3 기본값을 B2로 바꾸지 않는다.
- Sealed 실패를 분석하거나 prompt/validator를 조정하지 않는다.
- Jira, Confluence, 사내 데이터, 인증과 write-back은 포함하지 않는다.
